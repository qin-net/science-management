# 技术决策记录

格式：背景 → 决定 → 后果。偏离开发文档的决定必须写明原因。

## D-001 本机无 Docker，用内嵌 PostgreSQL 做开发和测试数据库

- **背景**：开发文档选 PostgreSQL + pgvector，SQLite 会让后续的部分唯一索引、JSONB、`SKIP LOCKED`、向量能力无法验证。本机没有 docker、podman、psql、brew。
- **决定**：开发和测试用 `pgserver` 0.1.4 内嵌的真实 PostgreSQL 16.2 + pgvector 0.6.2（已实测启动并 `create extension vector`）。业务代码只依赖 `DATABASE_URL`；另提供 `docker-compose.yml`，但本机无法验证，标为未验证。**不使用 SQLite 替代。**
- **后果**：`pgserver` 只是开发依赖，不进入生产路径；pgvector 版本较旧，P0.5 引入向量前要复核是否满足需要。

## D-002 PDF 默认解析器用 pypdfium2，Docling 作为可选独立环境解析器

- **背景**：开发文档首选 Docling，但它依赖 torch 和模型下载，环境约 1.2 GB，主环境引入成本高。阅读器定位只需要可靠的文字坐标。
- **决定**：内置 `pdfium` 解析器，秒级返回真实文字与坐标，但不识别结构。Docling 放在独立 Python 环境，经子进程调用，由 `DOCLING_PYTHON` 启用。解析器都走同一块契约。实测结果见 [spike 记录](./spikes/2026-10-30-upstream-candidates.md)。
- **后果**：默认切片没有章节、表格、公式识别，界面和警告如实说明。`READ-02` 保持“进行中”。

## D-003 账号先用内置邮箱密码，Keycloak 延后

- **背景**：开发文档 P0 选 Keycloak，需要 Java 服务；本机无容器环境，P0 切片会被部署阻塞。
- **决定**：P0 用内置账号（Argon2id、服务端会话、HttpOnly Cookie）。权限判断集中在 `security.py`，以后替换身份来源时不影响资源授权。
- **后果**：无账号恢复、无限流。不适合公网部署。生产前必须接入 OIDC 或补齐这些能力，已列入下一步。

## D-004 任务队列用 PostgreSQL 表 + 租约，暂不引入 Redis/Temporal/LangGraph

- **背景**：开发文档 12.1 建议先用 Outbox 与事件表，14.3 要求租约与心跳。
- **决定**：`jobs` 表用 `FOR UPDATE SKIP LOCKED` 领取，租约续期；完成提交用 `lease_owner + attempts` 做 fencing，迟到的旧 Worker 无法写入。业务变更和事件在同一事务。
- **后果**：吞吐足够 P0。LangGraph 在 P1.2 引入，负责 Agent 内层，不替代这张表。

## D-005 解析在子进程运行

- **背景**：线程里跑解析器无法强制超时和取消，原生库崩溃会带走 Worker；Docling 也必须在另一个 Python 环境运行。
- **决定**：所有解析器都是子进程，结果写临时 JSON。Worker 负责超时、取消（杀进程组）和续租。
- **后果**：每次解析多一次进程启动。子进程隔离**不是安全沙箱**。

## D-006 文献 API 嵌套在项目路径下

- **背景**：开发文档 14.4 的 `POST /api/v1/papers/import` 是拟定契约，项目归属要放在请求体里。
- **决定**：改为 `/api/v1/projects/{id}/papers`，归属由路径决定，资源不属于该项目时直接 404。DOI/arXiv 导入在 P0.3 再定入口。
- **后果**：跨项目隔离由路由结构直接保证。

## D-007 前端暂不引入 Tailwind 与 shadcn/ui

- **背景**：开发文档选 shadcn/ui + Tailwind，但切片页面很少，首要风险是 PDF.js 定位。
- **决定**：用 CSS 变量落实文档 12.2 的配色，组件手写。页面增多（P0.6 驾驶舱）时再引入。
- **后果**：之后需要一次样式迁移，代价可控。

## D-008 成员权限只到 Workspace 级

- **背景**：PROMPT P0.1 要求成员/权限边界和跨项目隔离；P2.4 才是完整的项目成员授权。
- **决定**：P0 的成员关系在 Workspace 级；项目隔离指资源不能经其他项目路径访问。项目级 ACL 留给 P2.4。
- **后果**：同 Workspace 成员互相可见全部项目。这是产品边界，界面和规格都写明，避免被理解成项目级私密。

## D-009 OpenAlex 必须按付费额度设计

- **背景**：开发文档写“上线时核实 key、额度与费用”。2026-10-30 实测：无 key 时同一 IP 共享每日 $0.10 预算，响应头 `x-ratelimit-cost-usd: 0.001`，全文 `search` 单次 $0.001，过滤查询实测 $0.0001；免费 key 每日 $1。
- **决定**：P0.3 的适配器必须支持 `OPENALEX_API_KEY`，读取 `x-ratelimit-*` 头，把预算耗尽（429）作为来源降级如实展示，并缓存响应。
- **后果**：P0.3 规格须包含额度处理。

## D-011 上传用原始请求体而不是 multipart

- **背景**：`python-multipart` 解析时会先把内容写入临时文件，无法在接收中途按项目权限和大小拒绝，也多一个依赖。
- **决定**：`POST /projects/{id}/papers` 的请求体就是 PDF 字节，文件名走查询参数。先校验登录和权限，再读请求体；已移除 `python-multipart`。
- **后果**：无法在一个请求里传多个文件或附带字段，批量上传由前端逐个发起。

## D-012 CSRF 用来源白名单

- **背景**：前端经 Next.js rewrite 代理 API，浏览器发出的 `Origin` 是前端地址，后端收到的 `Host` 可能是内部地址，原来的 Origin==Host 判断会拒绝合法请求。
- **决定**：写请求的 `Origin` 必须在 `ALLOWED_ORIGINS` 内，或与 `Host` 同源；无 `Origin` 的请求放行（非浏览器客户端），会话 Cookie 同时用 `SameSite=Lax`。登录和注册也经过这一检查。
- **后果**：部署时必须配置 `ALLOWED_ORIGINS`，否则前端写操作全部 403。

## D-010 暂缓 PaperAgent，写作走组装路线的准备

- **背景**：2026-10-30 核查 `songhahaha66/PaperAgent`：根目录无 LICENSE（`raw.../master/LICENSE` 为 404），GitHub 侧栏不显示许可证；2026-10-29 刚合入 2.0 重构（`82f7769`）；要求 Python 3.14+、PostgreSQL、OpenSandbox。
- **决定**：无许可证即不能假定有使用、修改或分发权利，**不下载运行、不复制代码**。P1.4 默认走开发文档第 6 节的组装路线，除非许可明确。
- **后果**：P1.4 规格须重新判断。

## D-013 检索 API 嵌套在项目下，限速和冷却状态放在 PostgreSQL

- **背景**：开发文档 14.4 把 `papers/search` 与 `papers/import` 放在顶层。检索结果要标记「已在项目中」，导入要按项目去重和校验权限。arXiv 条款要求所有机器合计每 3 秒不超过一次请求、同一时间一个连接，OpenAlex 额度由所有人共用（D-009），进程内计数在多进程下失效。
- **决定**：路径改为 `/projects/{id}/papers/search` 与 `/import`（同 D-006）。间隔、冷却、额度和响应缓存存 PostgreSQL，arXiv 与 Crossref 的串行用会话级咨询锁。不引入 Redis（D-004）。
- **后果**：每次外部请求前多几次数据库往返，量级远小于外部请求延迟；API 多进程部署时行为正确，需要两个真实进程的测试。

## D-014 外部响应一律当不可信数据，XML 用 defusedxml

- **背景**：三个来源是第三方，内容含任意文本；arXiv 返回 Atom XML；标准库 XML 解析器默认可能展开实体。
- **决定**：新增依赖 `defusedxml` 解析 XML；响应体设 2 MB 上限；标题和摘要只当文本，Crossref 的 JATS 标签在适配器里剥除；导入时服务端自己取元数据，不接受客户端提交的元数据；不下载开放获取链接指向的 PDF。
- **后果**：多一个小依赖；暂时不能一键拉取 PDF，用户仍上传 PDF。

## D-015 排序用名次融合并如实标注，不声称相关性

- **背景**：LIT-10 要求「相关性与引用数分别展示」。还没有嵌入模型或 LLM，三个来源的分数不可比。
- **决定**：用各来源名次的倒数融合（k=60）排序，响应里 `ranking` 标明方法，界面写「按各来源名次融合，不是相关性评分」；引用数分来源展示，不相加。
- **后果**：排序质量没有评测，不作为质量声明；有嵌入后再重新设计并评测。

## D-016 笔记存纯文本，批注的引用由服务端写入快照

- **背景**：开发文档 READ-08 要求批注存页码、坐标和原文哈希，笔记用 Tiptap。块在重新解析后可能变化（块只写一次，新任务写新块），笔记需要说清自己针对的是哪段原文。
- **决定**：笔记正文按纯文本保存和显示；批注只接收 `version_id` 与 `block_id`，页码、原文、哈希、坐标由服务端从块读取并存为快照；读取时按「同页同哈希」重新定位，找不到就标 `stale`，不猜。Tiptap 不引入。
- **后果**：没有富文本和任意区间高亮；块在换解析器后多半失效；重复文字的块可能被定位到同页另一个相同的块（已知限制）。

## D-017 总结、翻译、动机分析等需要模型的功能暂不实现

- **背景**：P0.4 要求翻译与总结，且「没有来源支撑的内容明确标注」。仓库没有配置任何模型，也没有模型供应商、预算或隐私方面的决定。把论文原文发给第三方模型会把用户的未发表资料传出本机，这是需要用户确认的事项，不是我可以替用户默认的。
- **决定**：本切片只做笔记与批注（不依赖模型）。READ-06、READ-11、READ-12 保持「未做」。不写假的或固定输出的实现，不放占位按钮。等用户给出供应商、密钥来源、费用上限和是否允许发送全文后，再单独写规格。
- **后果**：P0.4 与 P0.5 的助手问答部分（需要模型）阻塞在这个决定上；P0.5 的任务生命周期和 P0.6 的驾驶舱不依赖模型，可先做。
- **更新（2026-11-01）**：用户决定使用 Anthropic 的 Messages API，并允许把论文文本发送给外部服务。供应商与隐私两项已定；费用上限用户没有给出，规格里的默认值是我设的占位，见 D-021。模型相关功能解除阻塞，从论文问答（READ-21）开始，见 specs/007。

## D-018 任务自建，状态可任意流转，逾期由服务端按 UTC 日期算

- **背景**：开发文档说明默认自建轻量 Task，已有 Plane 时才同步。看板要有状态、负责人、筛选（PROJ-02）。
- **决定**：自建 `tasks` 表。五个状态之间可任意流转，只对「受阻必须写原因」「完成记录完成时间」做硬性规则；这些规则同时由数据库 CHECK 和接口保证。任何成员可改任何任务，删除限创建者或管理员。用下拉框改状态，不做拖拽。逾期只由服务端算，以 UTC 日期为「今天」。
- **后果**：不接 Plane；没有依赖、里程碑、评论；东八区早上 8 点前看到的「今天」晚一天；AI 任务草案与基础助手仍阻塞在 D-017。

## D-019 驾驶舱只展示计数与「我的待办」，不给出进度百分比

- **背景**：HOME-01 要求科研进度总览。系统里没有可以据此计算「进度」的定义（没有里程碑，没有读过的记录，没有方向分类）；任何百分比或评分都需要编造权重。
- **决定**：总览只展示库里的真实计数（项目、文献、任务状态、逾期）、跨项目的「我的待办」和最近动态；口径写在页面上；全部由服务端算，逾期复用任务接口的同一个函数；不画图表，不给评分。归档项目的任务不进汇总和「我的待办」。
- **后果**：HOME-01、HOME-03 只能标「进行中」；有里程碑和阅读记录后再设计进度指标。项目数很多时没有分页（已知限制）。

## D-020 引用导出用交换格式，条目类型统一为通用类型

- **背景**：READ-10 要求引用导出。库里有标题、作者、年份、DOI、arXiv ID、`venue`，但没有「条目类型」，页码、卷期、出版社也没有。
- **决定**：导出 BibTeX 与 RIS 两种参考文献工具通用的交换格式；条目类型统一用 `@misc` 与 `TY  - GEN`，`venue` 放在 `howpublished` 与 `T2`；缺失字段整行不写，没有标题的文献不导出；不做 CSL 样式渲染。文字一律折空白并转义；链接只由校验过的 DOI 与 arXiv ID 拼出。
- **后果**：参考文献工具里这些条目显示为「其他」类型，用户需要在工具里改类型；老的 BibTeX 对 Unicode 需要自行转换；READ-10 只能标「进行中」。引用键由元数据生成，元数据变了键会变。

## D-021 模型调用走 Anthropic Messages API，答案的出处由服务端从库里取，不信任模型的引文

- **背景**：D-017 解除阻塞。论文文本是不可信输入（可含“忽略以上指令”之类的内容），模型也可能编造引文；而本项目的要求是「没有来源支撑的内容明确标注」。
- **决定**：用 `httpx` 直接调 `POST /v1/messages`，不引入 SDK（与文献来源的做法一致，也便于用本地假服务测试）。密钥只从环境变量 `ANTHROPIC_API_KEY` 读取，没有密钥时接口返回 503 `model_not_configured`，界面说明原因，不退化成固定输出。模型名、基础地址、输出上限、每用户每分钟与每日请求数都可配置。给模型的每个文本块带编号，用结构化输出（`output_config.format` 的 `json_schema`）要求模型返回「分段答案 + 引用的块编号」（Opus 5.5、Sonnet 5.5、Fable 5.1 不支持强制工具调用，官方文档 2026-11-01 核对）；服务端核对编号都在本次提供的块里，不在的丢弃并标注，界面上展示的证据原文一律从库里的块取，不用模型复述的文字。无证据的分段标为「无出处」。每次调用记录模型名与用量，不记录问题和回答的文字到日志或事件。
- **后果**：问题与所选文献文本会发送给 Anthropic，界面在提问处明示；费用上限的默认值（每用户每日 50 次、单次输出 1500 token）是占位，需要用户确认；没有向量检索，单次提问可带的文本有字数上限（超过时拒绝并要求缩小范围），多篇大范围问答留给后续；真实 API 的行为在没有密钥时无法验证，只用本地假服务测试契约。

## D-022 「有笔记」代替「已读」，时间轴只做按天的活动计数

- **背景**：HOME-06 要「阅读数量」，HOME-07 要「科研时间轴」。系统没有阅读记录（打开文献不写任何东西），也没有里程碑对象。
- **决定**：只展示库里能直接数出来的东西：已解析的文献数、至少有一条笔记或批注的文献数（按文献去重，项目笔记不算），以及最近 14 个 UTC 日期里按天、按文献/笔记/任务/项目四类的事件数。名称里不用「已读」；口径写在页面上，并说明文献类包含解析的系统事件。不加阅读追踪，不按人拆分，不画图表库的图。
- **后果**：HOME-06、HOME-07 只能标「进行中」；方向、知识覆盖、里程碑、倒计时都没有。以后若要「读过」，需要明确的用户动作（例如标记已读）作为数据来源，另写规格。`research_events` 没有按工作区和时间的索引，事件量大时活动查询需要补索引。
